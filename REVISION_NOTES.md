# Revision Notes: AI Engineering Fundamentals

Course: Scott Moss, [AI Engineering Fundamentals](https://master.dev/courses/ai-engineering/). The project is an agentic chat that draws diagrams on an Excalidraw canvas.

## 1. The app in one paragraph

You chat with an agent and it draws and edits diagrams on a live Excalidraw canvas. The agent runs on a Cloudflare Durable Object and streams over WebSocket. It calls tools, some in the browser and some on the server, and loops until the diagram is done. Its quality is measured by an eval suite in Braintrust, which is used to improve it over time.

## 2. Why this is seen as best practice

- **Evals before features.** Prompts and tools are changed against a golden dataset, so you measure rather than guess. Change one variable at a time.
- **Deterministic scorers first.** Cheap, repeatable checks (schema, structure, bindings) catch most regressions. An LLM judge can come later.
- **One agent core, two entry points.** The same system prompt and loop serve the live app (`streamText`) and the evals (`generateText`), so they can't drift apart.
- **Context engineering.** The prompt carries the role, hard rules, a layout grid, diagram patterns and worked examples. The canvas is serialised to text on demand via `queryCanvas`.
- **Tools give the model hands.** Small CRUD tools beat one "generate everything" call, and the model can fix its own mistakes (e.g. overlap feedback returned from `addElements`).
- **Stateful, streaming agents.** Durable Objects keep per-session state, and the UI streams text and tool status.
- **RAG and web search** ground answers in knowledge the model doesn't have.

### Context format: TOON

[TOON](https://toonformat.dev) (Token-Oriented Object Notation) is a compact, human-readable format for passing structured data to an LLM. Field names are declared once for an array of same-shaped objects, with CSV-style rows beneath, so it avoids JSON's repeated keys, quotes and braces. The claim is roughly 30 to 60 percent fewer tokens on uniform arrays, with equal or better accuracy.

The principle from the course: **JSON is a wire format for machines, not a context format for language models.** Canvas elements are an array of same-shaped objects, which is TOON's sweet spot. Note that the lesson recommends it, but this repo's `canvas-state.ts` currently builds its own compact text summary and doesn't depend on `@toon-format/toon`.

### What is a Durable Object?

A Cloudflare Worker class with its own persistent (SQLite-backed) storage, and only one live instance per ID. That makes it a natural home for per-session state and long-lived WebSocket connections. Here `DesignAgent` (an `AIChatAgent`) is one, declared in `wrangler.toml`. There is one per chat session, and it persists the messages.

**Is it just persistence?** No, persistence is only one part. A Durable Object gives you three things together:

- **A single instance per ID.** Every request and WebSocket for a session reaches the same object, so there are no race conditions and no locks to manage.
- **Storage next to the compute.** State lives with the code that uses it, so reads and writes are fast and need no separate database call.
- **Long-lived connections.** The object holds the WebSocket open, which suits streaming chat and agent loops that run for many steps.

**Is it new?** No, it's an established Cloudflare primitive. What's recent is its use as the standard home for AI agents, via the Cloudflare Agents SDK.

**Why is it better than the usual approach?** The alternative is a stateless server (plain Workers, Lambda, etc.) plus an external database or Redis, and often a separate pub/sub layer to push messages to open sockets. You'd load and save state on every request and coordinate concurrent requests yourself. A Durable Object collapses that into one unit per session. It isn't always better, though: it ties you to Cloudflare, and a single object handles one session's traffic, not global queries across all sessions.

## 4. Tools

| Tool | Runs | Purpose |
|---|---|---|
| `addElements` | Browser | Create shapes, arrows, lines and text. Returns overlap info so the agent can self-correct. |
| `updateElements` | Browser | Patch existing elements by id. |
| `removeElements` | Browser | Delete elements by id. |
| `queryCanvas` | Browser | Text summary of the current canvas. Called before modifying anything. |
| `searchWeb` | Server | Tavily lookup for current information. |
| `searchKnowledge` | Server | RAG over the Upstash knowledge base. |

The first four are the CRUD controls for Excalidraw. Browser tools have no `execute` on the server, so `onToolCall` in `App.tsx` runs them against the live canvas.

### What is the corpus for?

`data/corpus/` holds six markdown reference docs (Workers request lifecycle, k8s pod networking, OAuth code flow, Postgres write path, startup org structure, general best practices). `npm run embed` (`src/rag/embed.ts`) uploads them to Upstash Vector. The `searchKnowledge` tool then retrieves relevant content, so the agent can ground diagrams in that knowledge instead of guessing. This is RAG.

## 5. Evals

- Braintrust project "Diagram Agent", run with `npm run eval`.
- Dataset is `golden_2.json`: 31 cases (create, modify, domain, edge).
- Seven custom, code-based scorers: `schema`, `structure`, `toolChoice`, `labelKeyword`, `connectivity`, `boundArrows`, `boundLabels`.
- The loop: run the eval, inspect failures, change one thing (prompt, schema or tool), re-run, compare.

### What do scorers do?

A scorer is a function that takes the case input, the agent's output and the expected values, and returns a score from 0 to 1 (or null if it doesn't apply). Braintrust runs every scorer on every dataset case and records the results per experiment. That gives a score per dimension (schema, structure, tool choice, connectivity, etc.) that can be compared between runs. Ours are deterministic code checks, not LLM judges.

## 6. SDKs and setup

- **`ai` (Vercel AI SDK v6):** `streamText`, `generateText`, `tool` and `stepCountIs(8)` for the agent loop.
- **`@ai-sdk/anthropic`:** the model provider.
- **`agents` + `@cloudflare/ai-chat`:** `AIChatAgent` on the server, `useAgent` / `useAgentChat` in React.
- **`zod` v4:** tool input schemas. The element schema is a `z.union` because Anthropic strict mode accepts `anyOf`.
- **`braintrust`:** the eval runner.
- **`@excalidraw/excalidraw`, React 19, Vite** (with the Cloudflare plugin): the frontend.
- **`@upstash/vector`:** the RAG client.
- **VitePress:** renders the lesson notes in `lessons/`.
